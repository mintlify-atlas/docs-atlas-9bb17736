The JupyterLab image is a standard Docker container that exposes port 8888. It is designed to deploy in one command on any platform that can run a Dockerfile. The only mandatory runtime configuration is `JUPYTER_TOKEN` — a secret string that gates access to the notebook server. Every deployment path below sets that token through the platform's secret or environment variable mechanism so the key never bakes into the image.

<Warning>
  **Single container = shared kernel.** In the default setup, every person who opens the JupyterLab URL shares one Python kernel and one copy of the API key. This is fine for a solo demo or a proctored class working one at a time. For a real multi-learner assessment requiring isolation, deploy **one container per learner** — front the image with JupyterHub using `jupyterhub-ltiauthenticator` for Lumen/LTI 1.3 integration.
</Warning>

## Deployment options

<Tabs>
  <Tab title="Hugging Face Spaces">
    Hugging Face Spaces is the fastest free option. Free-tier CPU Spaces run **Labs 1 and 2** comfortably. Labs 3–5 require the heavier packages (`chromadb`, `langgraph`, `fastembed`) and a paid or upgraded Space.

    <Steps>
      <Step title="Create a new Space">
        Go to [huggingface.co](https://huggingface.co) → **New Space** → choose **Docker** as the SDK → select the **blank** template.
      </Step>
      <Step title="Set the Space to private">
        In **Settings → Visibility**, switch the Space to **Private** so only invited collaborators can open the URL.
      </Step>
      <Step title="Upload the lab files">
        Upload every file from the `GenAILabJupyter/` folder to the Space repo root:
        ```text
        Dockerfile
        requirements.txt
        jupyter_server_config.py
        README.md
        sandbox.py
        grader.py
        grader_tests.py
        RAG_Lab_Participant.ipynb
        RAG_Lab.ipynb
        content/          (entire directory)
        ```
      </Step>
      <Step title="Add the token secret">
        Go to **Settings → Secrets** and add:

        | Name | Value |
        |---|---|
        | `JUPYTER_TOKEN` | A long random string of your choice |
      </Step>
      <Step title="Open JupyterLab">
        Wait for the build to complete. Navigate to the Space URL. If prompted for a token, paste your `JUPYTER_TOKEN` value.

        You can also open JupyterLab directly with the token in the URL:
        ```text
        https://<user>-<space>.hf.space/lab?token=<JUPYTER_TOKEN>
        ```
      </Step>
    </Steps>

    <Note>
      Free CPU Spaces run Labs 1 and 2. To run Labs 3–5, uncomment the heavier packages in `requirements.txt` (`chromadb`, `langgraph`, `langchain-chroma`, `mcp`, `langchain-mcp-adapters`, `fastembed`) and use a Space with more RAM and CPU.
    </Note>
  </Tab>

  <Tab title="Render">
    Render supports Dockerfile deploys and environment variables natively.

    <Steps>
      <Step title="Create a new Web Service">
        In the Render dashboard, choose **New → Web Service** → **Deploy an existing image / Dockerfile** → point at your repository.
      </Step>
      <Step title="Set the runtime environment">
        Set the **Environment** to `Docker`. Choose an instance type with **at least 1 GB RAM** (the `Starter` plan or higher).
      </Step>
      <Step title="Add the token environment variable">
        Under **Environment Variables**, add:

        | Key | Value |
        |---|---|
        | `JUPYTER_TOKEN` | Your chosen secret token |

        Render automatically sets the `$PORT` variable; the `jupyter_server_config.py` already reads it:
        ```python
        c.ServerApp.port = int(os.environ.get("PORT", "8888"))
        ```
      </Step>
      <Step title="Deploy and open">
        Click **Create Web Service**. Once the deploy finishes, open:
        ```text
        https://<your-service>.onrender.com/lab?token=<JUPYTER_TOKEN>
        ```
      </Step>
    </Steps>
  </Tab>

  <Tab title="Railway / Fly.io">
    Both Railway and Fly.io support single-command Docker deploys from the project folder.

    **Railway**

    ```bash
    # From the GenAILabJupyter/ directory
    railway up
    ```

    Set `JUPYTER_TOKEN` in the Railway project's **Variables** tab. Railway assigns a public domain automatically.

    **Fly.io**

    ```bash
    # From the GenAILabJupyter/ directory
    fly launch
    ```

    In `fly.toml`, ensure the internal port matches:
    ```toml
    [[services]]
      internal_port = 8888
    ```

    Set the token secret:
    ```bash
    fly secrets set JUPYTER_TOKEN=your-secret-token
    ```

    Then deploy:
    ```bash
    fly deploy
    ```

    Open `https://<app-name>.fly.dev/lab?token=<JUPYTER_TOKEN>`.
  </Tab>

  <Tab title="Docker Compose (VM)">
    For any Linux VM with Docker installed, use the included `docker-compose.yml`.

    <Steps>
      <Step title="Edit the token">
        Open `docker-compose.yml` and replace `changeme` with a strong secret token before running anything:

        ```yaml
        environment:
          SANDBOX_MODE: mock
          JUPYTER_TOKEN: "changeme"        # replace this
          CULL_IDLE: "3600"
        ```
      </Step>
      <Step title="Build and start the container">
        ```bash
        docker compose up --build -d
        ```
      </Step>
      <Step title="Open JupyterLab">
        ```text
        http://<host>:8888/lab?token=<your-token>
        ```

        For production use, put the container behind **nginx** or **Caddy** with TLS termination.
      </Step>
    </Steps>

    The full `docker-compose.yml`:

    ```yaml
    # Local / VM run:  docker compose up --build   ->  http://localhost:8888
    services:
      lab:
        build: .
        ports:
          - "8888:8888"
        environment:
          SANDBOX_MODE: mock
          JUPYTER_TOKEN: "changeme"        # open http://localhost:8888/lab?token=changeme
          # OPENAI_API_KEY: "sk-..."        # optional: then set SANDBOX_MODE=openai in the notebook
          CULL_IDLE: "3600"
        volumes:
          - ./work:/home/learner/work      # persist the learner's notebooks between restarts
    ```

    <Note>
      The `volumes` mapping persists the learner's notebook work between container restarts. Without it, any changes made in the browser are lost when the container stops.
    </Note>
  </Tab>
</Tabs>

## Dockerfile internals

The image is built from `python:3.11-slim` and kept deliberately lean. Key decisions are documented here so you can adapt the image for your own infrastructure.

```dockerfile
FROM python:3.11-slim

# --- system deps kept minimal ---
RUN apt-get update && apt-get install -y --no-install-recommends \
        git curl ca-certificates && \
    rm -rf /var/lib/apt/lists/*

# --- non-root user (Hugging Face Spaces requires uid 1000) ---
RUN useradd -m -u 1000 learner
ENV HOME=/home/learner \
    PATH=/home/learner/.local/bin:$PATH \
    SANDBOX_MODE=mock \
    PYTHONDONTWRITEBYTECODE=1

WORKDIR /home/learner/work

# --- python deps ---
COPY --chown=learner:learner requirements.txt .
RUN pip install --no-cache-dir --upgrade pip && \
    pip install --no-cache-dir -r requirements.txt

# --- lab content (read-only helpers + the notebooks the learner opens) ---
COPY --chown=learner:learner sandbox.py grader.py grader_tests.py ./
COPY --chown=learner:learner content ./content
COPY --chown=learner:learner RAG_Lab_Participant.ipynb RAG_Lab.ipynb ./
COPY --chown=learner:learner jupyter_server_config.py /etc/jupyter/jupyter_server_config.py
COPY --chown=learner:learner README_IN_LAB.md ./README.md

USER learner
EXPOSE 8888

# token comes from the JUPYTER_TOKEN env var (set it as a platform secret);
# empty means no token (fine only when the platform already gates access).
CMD ["jupyter", "lab", "--config=/etc/jupyter/jupyter_server_config.py"]
```

<Info>
  The `learner` user runs at uid 1000 because Hugging Face Spaces requires all container processes to run as uid 1000. This uid also works correctly on Render, Railway, Fly.io, and standard Linux VMs.
</Info>

## Enabling real LLM mode

Mock mode works for all five labs and requires no external credentials. To use a real language model, add the API key as a **platform secret** — never hard-code it in the image.

| Platform | Where to add the secret |
|---|---|
| Hugging Face Spaces | Settings → Secrets |
| Render | Environment Variables |
| Railway | Variables tab |
| Fly.io | `fly secrets set OPENAI_API_KEY=sk-…` |
| Docker Compose | `environment:` block in `docker-compose.yml` |

Once the key is available in the container environment, switch the notebook's setup cell to use it:

```python
import os
os.environ["SANDBOX_MODE"] = "openai"   # or "claude" for Anthropic
```

<Tip>
  You can also set `ANTHROPIC_API_KEY` if you want to run the labs against Claude. The `sandbox.py` helper reads `SANDBOX_MODE` and routes calls to the correct provider automatically.
</Tip>

## VS Code alternative

The repository also includes `Dockerfile.codeserver`, which swaps JupyterLab for **code-server** (VS Code in the browser) while mounting the same `content/`, `grader.py`, and `sandbox.py`. Build from `Dockerfile.codeserver` instead of `Dockerfile` — everything else in your deployment stays the same.

<Note>
  For the current labs — which build a step-by-step RAG pipeline across cells — JupyterLab is the stronger fit. Code-server is better suited to a future multi-file "build and ship an agent" capstone project.
</Note>
