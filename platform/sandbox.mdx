The sandbox runtime (`sandbox.py`) is the invisible scaffolding behind every learner "Run". Before the platform `exec()`s any learner-submitted code, it prepends a preamble that imports all sandbox helpers into the execution namespace. This means learners can call `get_chat_model(MODE)`, `make_vectorstore(chunks, embeddings)`, or `get_tools()` directly — without needing to wire up API clients, manage credentials, or worry about which backend is active. The sandbox is also responsible for resolving the active mode (`openai`, `claude`, or `mock`) from environment variables, and for gracefully degrading when optional packages are absent.

## Modes

The sandbox operates in one of four modes, selected by the `SANDBOX_MODE` environment variable or passed explicitly to each factory function. The `auto` mode is the default and walks down a priority chain at runtime.

<Tabs>
  <Tab title="openai">
    Uses `langchain_openai.ChatOpenAI` for chat and `OpenAIEmbeddings` for embeddings. Requires `OPENAI_API_KEY` to be set in the environment. Default chat model: `gpt-4o-mini` (overridable via `OPENAI_MODEL`). Default embedding model: `text-embedding-3-small` (overridable via `OPENAI_EMBED_MODEL`).
  </Tab>
  <Tab title="claude">
    Uses `langchain_anthropic.ChatAnthropic` for chat and local FastEmbed ONNX embeddings (Anthropic has no embeddings API). Requires `ANTHROPIC_API_KEY`. Default model: `claude-sonnet-4-5` (overridable via `ANTHROPIC_MODEL`).
  </Tab>
  <Tab title="mock">
    A fully local `BaseChatModel` that answers from a retrieved `Context:` block in the prompt — no network, no API key. **Demo only.** The mock model cannot emit tool calls, so agent and multi-agent labs require a real LLM mode.
  </Tab>
  <Tab title="auto">
    Resolves at runtime: `openai` if `OPENAI_API_KEY` starts with `sk-`, else `claude` if `ANTHROPIC_API_KEY` starts with `sk-ant-`, else `mock`. This is the default when `SANDBOX_MODE` is not set.
  </Tab>
</Tabs>

<Note>
  API keys are read exclusively from environment variables or server-side secrets. They are never hard-coded in source files and are never sent to the browser. The Streamlit deployment injects them server-side before each Run.
</Note>

## Constants

The sandbox exposes several path and model-name constants that learner code and the grader can reference directly.

| Constant | Value |
|---|---|
| `SAMPLE_PDF` | `content/_data/sample_knowledge_base.pdf` |
| `QUESTION_SET_PDF` | `content/_data/RAG_Question_Set.pdf` |
| `MCP_SERVER_PATH` | `mcp_server.py` (absolute, same directory) |
| `DEFAULT_OPENAI_CHAT` | `gpt-4o-mini` (env: `OPENAI_MODEL`) |
| `DEFAULT_OPENAI_EMBED` | `text-embedding-3-small` (env: `OPENAI_EMBED_MODEL`) |
| `DEFAULT_ANTHROPIC_CHAT` | `claude-sonnet-4-5` (env: `ANTHROPIC_MODEL`) |
| `DEFAULT_FASTEMBED` | `BAAI/bge-small-en-v1.5` (env: `FASTEMBED_MODEL`) |

## Preamble Injected Before Learner Code

Every time a learner clicks **Run**, the platform prepends this exact preamble to their code before calling `exec()`. The `PREAMBLE_IMPORTS` constant in `grader.py` mirrors it so the grader always executes under the same environment:

```python
from sandbox import (get_chat_model, get_embeddings, get_tools, split_docs,
                     load_sample_docs, make_vectorstore, supports_tool_calling,
                     mcp_stdio_config, resolve_mode,
                     SAMPLE_PDF, QUESTION_SET_PDF, MCP_SERVER_PATH)
```

The full preamble (generated by `grader.preamble(mode)`) also sets `SANDBOX_MODE` in `os.environ` and exports the resolved `MODE` string so learner code can pass it to factory functions without needing to call `resolve_mode()` directly.

## Public Functions

### `resolve_mode`

Resolves a requested mode string to one of `"openai"`, `"claude"`, or `"mock"`.

<ParamField path="requested" type="str | None">
  The mode string to resolve. Accepts `"openai"`, `"claude"`, `"anthropic"` (alias for `"claude"`), `"mock"`, `"auto"`, or `"real"` (alias for `"auto"`). If `None`, falls back to the `SANDBOX_MODE` environment variable, then to `"auto"`.
</ParamField>

<ResponseField name="return" type="str">
  Always one of `"openai"`, `"claude"`, or `"mock"` — never `"auto"` or `"real"`.
</ResponseField>

```python
mode = resolve_mode("auto")   # → "openai" if OPENAI_API_KEY set, else "claude", else "mock"
mode = resolve_mode("anthropic")  # → "claude"
mode = resolve_mode(None)     # reads SANDBOX_MODE env var
```

### `get_chat_model`

Factory that returns a `BaseChatModel` for the active backend.

<ParamField path="mode" type="str | None">
  Mode to use. Passed to `resolve_mode()`. If `None`, uses `SANDBOX_MODE` environment variable.
</ParamField>
<ParamField path="model" type="str | None" optional>
  Override the default model name for the selected backend. Defaults to `DEFAULT_OPENAI_CHAT` or `DEFAULT_ANTHROPIC_CHAT` depending on mode.
</ParamField>
<ParamField path="temperature" type="float" default="0.0">
  Sampling temperature passed to the underlying LLM constructor.
</ParamField>
<ParamField path="**kw" type="Any" optional>
  Additional keyword arguments forwarded verbatim to `ChatOpenAI`, `ChatAnthropic`, or `MockGroundedChat`.
</ParamField>

<ResponseField name="return" type="BaseChatModel">
  A `ChatOpenAI`, `ChatAnthropic`, or `MockGroundedChat` instance, depending on the resolved mode.
</ResponseField>

```python
llm = get_chat_model(MODE)                          # auto-select by active mode
llm = get_chat_model("openai", model="gpt-4o")      # explicit model override
llm = get_chat_model("mock", temperature=0.7)       # mock for demos
```

### `get_embeddings`

Factory that returns an `Embeddings` object for the active backend.

<ParamField path="mode" type="str | None">
  Mode to use. Passed to `resolve_mode()`. In `openai` mode, returns `OpenAIEmbeddings`. In `claude` or `mock` mode, returns local `FastEmbedEmbeddings`.
</ParamField>
<ParamField path="model" type="str | None" optional>
  Override the default embedding model name. Defaults to `DEFAULT_OPENAI_EMBED` for OpenAI mode, or `DEFAULT_FASTEMBED` for local modes.
</ParamField>
<ParamField path="**kw" type="Any" optional>
  Additional keyword arguments forwarded to `OpenAIEmbeddings`.
</ParamField>

<ResponseField name="return" type="Embeddings">
  `OpenAIEmbeddings` in OpenAI mode; `FastEmbedEmbeddings` (local ONNX) in claude/mock mode. Falls back to `DeterministicFakeEmbedding(size=384)` if FastEmbed cannot be imported — a warning is printed and retrieval quality degrades.
</ResponseField>

```python
embeddings = get_embeddings(MODE)
embeddings = get_embeddings("openai", model="text-embedding-3-large")
```

### `make_vectorstore`

Builds a real vector store from pre-split document chunks.

<ParamField path="chunks" type="list[Document]">
  LangChain `Document` objects, typically produced by `split_docs()`. Passed directly to the store's `from_documents` constructor.
</ParamField>
<ParamField path="embeddings" type="Embeddings">
  Embeddings object used to encode the chunks. Typically the result of `get_embeddings()`.
</ParamField>
<ParamField path="collection" type="str" default="sandbox_kb">
  ChromaDB collection name. Each call with a unique collection name creates an isolated in-process store.
</ParamField>

<ResponseField name="return" type="VectorStore">
  A `langchain_chroma.Chroma` instance backed by `chromadb.EphemeralClient()` (in-process, no persistence). Falls back to `langchain_core.vectorstores.InMemoryVectorStore` if ChromaDB is not installed. If the embeddings call itself fails (e.g. invalid API key → 401), the function retries once with local `FastEmbedEmbeddings` and prints a loud warning.
</ResponseField>

```python
vectorstore = make_vectorstore(chunks, embeddings, collection="my_lab")
results = vectorstore.similarity_search("annual leave policy", k=3)
```

<Tip>
  The fallback chain is: **ChromaDB** → **InMemoryVectorStore** for the store, and **FastEmbed** → **DeterministicFakeEmbedding** for the embeddings. The platform always produces a working vector store — but embedding quality varies. Install `requirements-full.txt` for the best local experience.
</Tip>

### `split_docs`

Splits loaded `Document` objects into smaller chunks using `RecursiveCharacterTextSplitter`.

<ParamField path="docs" type="list[Document]">
  Raw documents as returned by a LangChain loader (e.g. `PyPDFLoader(...).load()`).
</ParamField>
<ParamField path="chunk_size" type="int" default="800">
  Maximum character length per chunk.
</ParamField>
<ParamField path="chunk_overlap" type="int" default="120">
  Number of overlapping characters between adjacent chunks to preserve context at boundaries.
</ParamField>

<ResponseField name="return" type="list[Document]">
  A flat list of `Document` chunks, each with inherited metadata from the source page.
</ResponseField>

```python
chunks = split_docs(documents, chunk_size=1000, chunk_overlap=200)
print(f"Split into {len(chunks)} chunks")
```

### `load_sample_docs`

Loads the bundled HR/policy PDF as a list of LangChain `Document` objects.

<ResponseField name="return" type="list[Document]">
  One `Document` per PDF page, each with `page_content` (extracted text) and `metadata` containing `source` (absolute path to the PDF) and `page` (zero-based page index). Uses `PyPDFLoader` from `langchain-community` if available; falls back to reading with `pypdf` directly so `langchain-community` is optional. If the PDF file is missing entirely, returns a single fallback `Document` whose `page_content` is the `_FALLBACK_TEXT` constant — a short HR policy excerpt covering casual leave (12 days), sick leave (10 days), earned leave (18 days), notice period (60 calendar days), travel policy (economy-class domestic), and medical insurance (INR 5,00,000 per policy year).
</ResponseField>

```python
documents = load_sample_docs()
print(f"Loaded {len(documents)} pages from the sample PDF")
```

### `get_tools`

Returns real LangChain `@tool`-decorated objects for the tool-calling and agent labs.

<ParamField path="names" type="list[str] | None" optional>
  Optional list of tool names to return. Valid names: `"calculator"`, `"word_count"`, `"kb_lookup"`. If `None` or omitted, all three tools are returned.
</ParamField>

<ResponseField name="return" type="list[BaseTool]">
  A list containing any combination of the three tools described below.
</ResponseField>

<AccordionGroup>
  <Accordion title="calculator — arithmetic expression evaluator">
    **Signature:** `calculator(expression: str) -> str`

    Evaluates a basic arithmetic expression using a safe AST-based evaluator — no `eval()`. Supports `+`, `-`, `*`, `/`, `**`, `%`, `//`, and unary negation.

    ```python
    # example call
    calculator("(2 + 3) * 4 ** 2")   # → "80"
    ```
  </Accordion>
  <Accordion title="word_count — whitespace-separated word counter">
    **Signature:** `word_count(text: str) -> int`

    Returns the number of whitespace-separated tokens in `text`. Simple and deterministic — useful as a baseline tool for verifying that an agent can handle non-LLM tool responses.

    ```python
    word_count("Hello world foo")   # → 3
    ```
  </Accordion>
  <Accordion title="kb_lookup — semantic search over the HR handbook">
    **Signature:** `kb_lookup(query: str) -> str`

    Loads the sample knowledge base PDF, splits it, builds a vector store, runs `similarity_search(query, k=2)`, and returns the top two passages (up to 400 chars each) joined by `---`. Returns `"no match found"` if the store is empty.

    ```python
    kb_lookup("annual leave entitlement")
    # → "Employees are eligible for 12 days of casual leave..."
    ```
  </Accordion>
</AccordionGroup>

```python
tools = get_tools()                          # all three
tools = get_tools(["calculator", "kb_lookup"])  # subset
```

### `mcp_stdio_config`

Returns the subprocess configuration dict for `langchain_mcp_adapters.MultiServerMCPClient`.

<ParamField path="server_name" type="str" default="sandbox">
  The key under which this server is registered in the `MultiServerMCPClient` config dict.
</ParamField>

<ResponseField name="return" type="dict">
  A dict of the form `{server_name: {"command": sys.executable, "args": [MCP_SERVER_PATH], "transport": "stdio"}}`. The `command` is always the same Python interpreter running the Streamlit app, so no separate virtual environment is needed.
</ResponseField>

```python
config = mcp_stdio_config("sandbox")
# → {"sandbox": {"command": "/usr/bin/python3", "args": ["/app/mcp_server.py"], "transport": "stdio"}}

from langchain_mcp_adapters.client import MultiServerMCPClient
async with MultiServerMCPClient(config) as client:
    tools = client.get_tools()
```

### `supports_tool_calling`

<ParamField path="mode" type="str | None">
  Mode to check. Passed to `resolve_mode()`.
</ParamField>

<ResponseField name="return" type="bool">
  `True` if the resolved mode is `"openai"` or `"claude"` (both support function/tool calling). `False` for `"mock"` — the mock model cannot emit tool-call messages and agent labs will fail silently if run in mock mode.
</ResponseField>

```python
if not supports_tool_calling(MODE):
    st.warning("Agent labs require OpenAI or Claude mode — mock cannot call tools.")
```

### `check_llm`

Makes a single minimal API call (`model.invoke("ping")` with `max_tokens=5`) to verify that the configured key and model name are valid.

<ParamField path="mode" type="str | None">
  Mode to check. Passed to `resolve_mode()`. In `mock` mode, no network call is made and the function returns `(True, "Mock mode — no key required.")` immediately.
</ParamField>

<ResponseField name="return" type="tuple[bool, str]">
  A `(ok, detail)` tuple. `ok` is `True` if the call succeeded; `detail` is a human-readable status string shown in the Streamlit sidebar. On failure, `detail` contains the exception class name and the first 280 characters of the error message.
</ResponseField>

```python
ok, detail = check_llm(MODE)
if not ok:
    st.error(f"LLM check failed: {detail}")
```
